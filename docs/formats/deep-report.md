## 教学型专题（读者要「懂」，不只要「拍板」）

触发：用户说「深度了解 / 讲清楚 / 概念 / 框架 / 方法论」，且读者不是同行。教学型仍可套 L2 的证据与红队，但结构与验收不同。

- **一题一问**：原话含两个问题（如「是什么」+「怎么用」）时，拆成两篇或两部分；本篇只答一个，桥另写。
- **标题用问题**：如「Palantir 到底卖什么？」，不用「概念澄清」「方法论内核」。
- **先场景，后术语**：第一节从读者熟悉的场景/问题开始，不先讲角色表、框架名、证据编号。
- **概念顺序**：问题 → 人话 → 例子 → 术语 → 反例 → 所以呢；术语四步缺一不出现。
- **一个贯穿案例**：每节至少一个例子；没有例子的段落删掉或补例子。
- **证据降噪**：正文只留 8–10 个关键 `[E##]`；其余进附录，别让编号盖过解释。
- **读者测试**：3 位读者 × 5 个问题，至少 4/5 能复述；记录 `reader-test-vN.md`。不通过先改再交。
- **篇幅**：每篇 3,500–4,500 字；不一次写两篇，先写第一篇，测试通过再写第二篇。
## 规则

- 子问题 4–8 节；每节 ≤1200 字；每节第一行是结论。
- 至少 8 条 A 级证据；关键数字两源；单源要标。
- 必有「反方与风险」：写最强反方论证 + 回应，不是套话。
- 必有「待核与未获取」：缺口、冲突、单源、打不开的页面。
- 必有「口径与假设」：范围、时间、关键假设、预测的失效条件。
- 红队记录放 `red-team-vN.md`，不塞进正文。
- 超过 9000 字：优先拆成主报告 + 附录，或降为 L1。

## 交付

结论卡 + 报告 + HTML + 红队记录；对话里一屏回执 + 文件卡片。
