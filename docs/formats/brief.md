# L1 简报（brief.md）

> 支持一次汇报或一个判断。1–2 页，手机能读完，结论卡 + 三节正文。

```json
{
  "key": "L1",
  "name": "简报",
  "max_chars": 1500,
  "min_chars": 400,
  "min_sources_total": 5,
  "min_sources_a": 3,
  "required_sections": ["结论卡", "关键发现", "待核", "来源"],
  "conclusion_card_fields": ["结论", "关键数字", "动作", "反证", "置信度"],
  "max_paragraph_lines": 5,
  "forbidden_patterns": ["综上所述", "由此可见", "值得注意的是", "随着", "赋能", "抓手", "闭环", "协同发力", "全面提升", "打造生态", "助力增长", "进一步", "不断", "切实", "扎实"]
}
```

## 结构

```
# 题目（结论式）
> 2026-10-19 · L1 简报 · 5 源 · 置信度中

## 结论卡
- 结论：……
- 关键数字：① … [E01] ② … [E02] ③ … [E03]
- 动作：① 谁 什么时候 做什么 ② …… ③ ……
- 反证：若 …… 成立，则本结论作废
- 置信度：中 —— 因为 ……

## 关键发现
### 1. 发现标题（结论式）
两句话 + 证据 + 所以呢。

### 2. ……
### 3. ……

## 正文（2–3 节，按子问题）
## 待核
## 来源
```

## 规则

- 正文 2–3 节，每节 ≤400 字。
- 关键发现最多 3 条；多了降为支撑。
- 至少 3 条 A 级证据；关键数字两源。
- 不写「背景」长节；背景压进结论卡或一句 SCQA。
- 不给「建议关注」；动作写到人、时间、事。

## 交付

结论卡 + 报告 + HTML；对话里一屏回执。
