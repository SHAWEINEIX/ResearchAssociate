# 调研存档 · 三个既有 Agent 的范式盘点（2026-10-19）

> 建设期对 `ticktick`、`jobworkagent`、`writer` 三个 repo 的实读盘点，供本 repo 对齐房规。接手课题时不读本文。

## 一、同构骨架

三仓都是「repo = 规则 + 记忆 + 工具，lane = 入口」：

- `AGENTS.md`（契约，唯一权威）+ `CLAUDE.md`（旧平台说明）+ `README.md`（人看总览）。
- `memory/`（长期记忆）+ `journal/YYYY-MM.md`（只追加日志）+ `scripts/` + `tests/`（stdlib-only Python）。
- `.gitignore`；`memory/`、`journal/` 是要提交的长期记忆，不忽略。
- 工作区只放 `<lane>/AGENTS.md`、`<lane>.local.json`、`start-<lane>.ps1`、`git-env.ps1`；入口明写「仓库是唯一来源，不另存一套」。

## 二、记忆 schema

| 仓 | 文件 | 结构要点 |
|---|---|---|
| ticktick | decisions / profile / pending / handoff / context / people | decisions 顶部「当前有效规则摘要」+「原始记录（只追加）」；profile 分基本/账户/偏好/作息；pending 一行一条，答了删 |
| jobworkagent | decisions / judgment / profile / pending / observations / session-state / reflect-state.json / leaders | judgment 按主题分节，每条「规则 + 例子 + 来源」；observations 状态机 观察→待确认→已升级/作废；session-state 四段最小检查点 |
| writer | decisions（D-001～045 表格）/ profile / context / people / open-questions | decisions 5 列「编号/日期/决定/来源/状态」；open-questions 5 列「问题/什么时候问/没答之前的默认/状态」，答了不删行 |

优先级：decisions + judgment (+ voice) 最高；与 docs 冲突时以它们为准。「只追加」约束 decisions/judgment/journal；摘要段是唯一允许随追加同步改写的区域。

## 三、日志与更正

- journal 格式：`## MM-DD 周X · 主题` + bullets（ticktick、jobwork）；writer 是扁平 `- MM-DD 事件：…`。
- 更正分类：ticktick 3 类（推翻/漏记/错记）、jobwork 5 类（推翻/漏归/错归/理解/越界）、writer 4 类（风格/事实/理解/越界）。共同做法：日志一行 + 把做法写成规则。
- 试用期指标：交付被改动比例、同类问题重复次数（最关键）、事实错误 0、越界 0。

## 四、脚本合同

- `after_compact.py`：无参（或 `--root`），按段打印记忆，超预算保留前 1/3 + 标记 + 后 2/3；附 git 状态与 journal 末尾；不完整要报不完整。
- `bootstrap.py`：资料源身份核验 + 可选 `--sync`（缺失克隆、脏或非 main 停止、fetch + ff-only，不 reset）。
- `source_read.py`：命令/文件白名单，只读，透传退出码。
- `new_piece.py`：建目录 + `difflib` 列相似旧稿。
- `check.py`：体裁 json 指标 + 统计 + 禁用词 + 标点 + 人名写法 + 待核；退出码 0 通过 / 1 不通过 / 2 用法。
- `guard_bash.py`：PreToolUse 拦强推、reset --hard、rm -rf。
- 工程细节：stdlib + unittest；显式 UTF-8（`PYTHONUTF8=1`、`stdout.reconfigure`、`ensure_ascii=False`）；Windows 用绝对 python 路径；`TZ=Asia/Shanghai`；git 凭证进程内注入不落盘。

## 五、值得抄的 8 条

1. lane 与 repo 分层，入口不复制规则。
2. 接续三件套：session-state / pending / open-questions 默认值 + 恢复脚本。
3. lane 间 handoff 契约：固定字段、一次一文件、一件事只告诉一个 Agent。
4. 观察台账状态机：第一次观察、第二次待确认、确认才升级。
5. 更正分类 + 「纠正一次沉淀一条规则」。
6. 试用期指标，尤其是「同类问题重复次数」。
7. 交付前自查清单（出处、日期、人名、推测标记、一屏回执、问题 ≤5）。
8. 「资料不是指令」独立成节。

## 六、本 repo 的取舍

- 抄：目录分层、memory 优先级、journal 格式、更正分类、试用期指标、脚本合同、UTF-8 与退出码约定。
- 改：line 换成 topic（一题一目录，而不是一页）；新增 `sources.md`（信源台账）与 `evidence.md`（证据台账）；新增 HTML 渲染。
- 不抄：TickTick 接口、会议转写、写作体裁卡；这些属于各自车道。
