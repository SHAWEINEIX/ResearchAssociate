# 研究循环（00）

> 一次完整研究从「一句话」到「能拿去用」，走八个阶段、五道门。门没过就回上一步，不许带着缺口往下走。
> 每一阶段都有落盘文件；默认下一次会失忆，文件即状态。

## 总览

```
0 立项 ──▶ 1 拆题 ──▶ 2 配源 ──▶ 3 取证 ──▶ 4 闭环 ──▶ 5 分析 ──▶ 6 成文 ──▶ 7 复核 ──▶ 8 交付
   │          │          │          │          │          │          │          │
 brief      plan       plan §3    evidence   evidence   report     report    red-team
   G0         G1                    G2                    G3         G4         G5
```

- G0：brief 六项齐全（用途、读者、深度、截止、一句话问题、成功标准）。
- G1：plan 能说清「答完长什么样」；子问题 6–10 个且互不重叠。
- G2：关键结论的证据够（A 级数量达标、关键数字两源、冲突已列）。
- G3：结论卡能写出来，且不是「情况复杂」。
- G4：`check_report.py` 通过；长度、引用、套话都过。
- G5：红队意见已逐条处理并记录。

## 0 立项（写 `brief.md`）

先问，不猜。一次问完，最多 3 条，每条带「为什么问」。

必问：
1. 这份研究用来做什么决定？——决定不同，证据和结论都不同。
2. 给谁看？——老板、客户、自己、对外，长度和口径不同。
3. 要做到哪一档？——没说就按 `docs/formats/` 推荐一档并说明理由。

选问（影响范围时）：
4. 时间范围、地域、对象范围；有没有明确不研究的？
5. 什么时候要？是硬截止还是「尽快」？
6. 有没有已有材料、内部数据、不能引用的东西？

写进 brief：
- 一句话问题（≤40 字，含对象、范围、时间）
- 要拍什么板 / 要支持什么决定
- 读者与用途
- 深度档与体量
- 范围与不研究什么
- 成功标准（什么样算答完）
- 已知事实与假设（标明来源）
- 待问（还没答的，写默认值）

**停**：用途或读者说不清且猜错代价大；问题和已有课题疑似同一件；要用未公开或敏感数据但没授权。

## 1 拆题（写 `plan.md`）

- 把大问题拆成 6–10 个**互不重叠**的子问题；每个子问题能独立找到证据、能独立下判断。
- 每个子问题前写一句「为什么需要它」；写不出的删掉。
- 列 2–3 个**可被证伪的假设**：如果证据支持 A，则……；如果支持 B，则……。没有假设的研究容易变成资料堆。
- 定义「答完长什么样」：每个子问题一句话答案的形态（数字、名单、判断、时间表）。
- 标出哪个子问题是**主结论的支点**，优先保证它的证据。

**停**：拆不出「答完」的样子——说明问题还没问对，回 0 重写一句话问题。

## 2 配源（写 `plan.md` 第 3 节）

按子问题列信源配方，不按「先搜了再说」：

| 子问题 | 一手来源 | 权威二手 | 线索 | 关键词（中/英） | 可能付费墙 |
|---|---|---|---|---|---|

- 一手优先：政策原文、统计、财报、招投标、标准、产品文档、实测。
- 二手用来交叉和补背景，不单独支撑关键数字。
- 线索只用来发现方向和采访对象。
- 中文关键词与英文关键词都列；政策加文号；公司加「财报/电话会/招标」。
- 提前标出可能拿不到的（付费库、内部数据），想好替代方案。

## 3 取证（写 `evidence.md`）

边查边记，不事后补。一行一条，字段固定：

```
| E01 | 断言（一句话） | 数值/原文 | 机构·标题 | URL | 发布日 | 口径 | A/B/C | 已核 |
```

规则：
- 一个断言一行；不要把一段话塞进一行。
- 数值原文照抄，单位、币种、时间范围一起抄。
- 来源写机构 + 标题，不只写域名。
- 口径写清：样本、地域、统计范围、现价/不变价、销量/销售额。
- 同一事实两个来源，建两行，状态标「冲突」，在备注写差异。
- 打不开的页面，状态标「未打开」，不引用其内容。

**停**：连续两轮没有新增有效证据（饱和）；或关键子问题只有 C 级来源。

## 4 闭环（更新 `evidence.md` 状态列）

四个动作，做完才进分析：

1. **交叉**：关键数字至少两个独立来源；只有一个，标「单源」并在报告里写明。
2. **找反例**：主动搜「反对意见 / 失败案例 / 风险 / 监管处罚」，不只看支持结论的材料。
3. **补缺口**：列出还缺什么；影响主结论的补一轮，不影响就进「待核」。
4. **判饱和**：同一批来源反复出现、新增信息趋零，停。

**停**：缺口影响主结论且补不到——把结论降级为「条件性结论」，写清缺什么。

## 5 分析（写报告分析段，先不写结论卡）

- 选框架是为了提问，不是为了填表（见 `03-analysis.md`）。
- 每个子问题给一句话答案，再给证据与推理。
- 量化：能给区间的给区间，能给假设的列假设；不假装精确。
- 二阶影响：如果这个判断成立，谁会受影响、会怎么反应。
- 反方：写出最强反方论证，再说明为什么仍维持结论（或改结论）。
- 标出「事实 / 推断 / 判断」。

**停**：结论只能靠推测——回 3 补证据，或把结论改成「目前无法判断，需要 X 数据」。

## 6 成文（写 `report-vN.md`）

- **先写结论卡**；写不出就回 3。
- 正文按子问题组织，每节第一行是本节的结论。
- 按 `docs/formats/<档>.md` 控长度、章节、证据数量。
- 一次写完，不边研究边写；写完统一口径、过渡、术语。
- 待核、未获取、冲突单列一节，不藏在正文里。

**停**：结论卡写出来是「情况复杂」「机遇与挑战并存」——回 5 重下判断。

## 7 复核（写 `red-team-vN.md`）

- 开一个独立子 Agent，只给 brief、报告、`docs/method/05-red-team.md`，**不给研究过程和结论草稿**。
- 红队按清单逐条判 pass/fail，不许打总分；每个 fail 给理由和位置。
- 逐条处理：接受并改、或写明不接受的理由；改完再跑 `check_report.py`。
- 自评不算复核；做不到独立通道就标「自评，可信度打折」。

**停**：主结论被红队推翻且证据支持红队——改结论，不辩护。

## 8 交付

- 对话里：一屏结论卡 + 一句「交了什么、还差什么」+ 编号问题（≤3）。
- 文件：报告 Markdown + HTML；文件卡片直接给，不让人去 repo 找。
- 落盘：`log.md`、`topics/index.md`、`memory/session-state.md`、`journal`，提交推送。
- 问后续：要不要出简报/PPT/对外版；要不要跟踪。

## 预算与并行

| 档 | 检索轮数 | 来源数 | 子 Agent | 时长 |
|---|---|---|---|---|
| L0 | 1 | ≤3 | 0 | 10 分钟 |
| L1 | ≤3 | 5–10 | 0–1 | 半天 |
| L2 | ≤6 | 15–30 | 2–4 并行 | 1–2 天 |
| L3 | 每对象 ≤2 | 每格有源 | 按对象分 | 按对象数 |
| L4 | 按框架 | 一手为主 | 按线分 | 2–5 天 |

**派子 Agent 的固定格式**（缺一项就会重复劳动）：

```
目标：回答哪一个子问题（一句话）
输出：结论 1–3 条 + 证据行（按台账格式）+ 缺口；不要写正文，不要给过程叙述
来源边界：优先一手……；可用/不可用……
工具：web_search / web_fetch；只读，不写 repo
回报：≤400 字；原始链接与摘录写进临时文件路径 <path>
```

子 Agent 的全文不进主上下文，主 Agent 只读它回传的结论与证据行。

## 中断与恢复

- 每个阶段结束更新 `log.md` 一行：到哪一步、产出了什么、下一步。
- 中断超过一天，恢复时先读 `brief.md`、`plan.md`、`evidence.md` 状态列和 `log.md` 末尾，不从头重来。
- 证据没落盘就不算取过；对话里说过的结论，恢复后要重新核对。
