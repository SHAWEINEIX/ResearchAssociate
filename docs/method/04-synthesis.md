# 成文与可读性（04）

> 报告不是研究过程的记录，是给读者做决定用的。读者只有几分钟：第一屏给结论，第一段给理由，后面才是证据。
> 这一篇管结构、语言、长度、排版，以及研究类文本的去 AI 味。

## 一、结构：结论先行

### 金字塔

1. 顶层：一句话结论（有方向、有判断）。
2. 第二层：3 条主论据（互相独立、合起来支撑结论）。
3. 第三层：每条论据下的证据（`[E##]`）、数据、案例。
4. 底层：口径、假设、待核、来源。

### SCQA 开场（可选，一段话）

- Situation：大家都知道的事实。
- Complication：变化或矛盾。
- Question：所以要回答什么。
- Answer：一句话结论。

不要写成四段；压成 3–4 句。

### 一屏结论卡（L1 以上必出）

```
结论：一句话，有方向、有判断。
关键数字：① ____ [E01]  ② ____ [E02]  ③ ____ [E03]
动作：① 谁 什么时候 做什么  ② ……  ③ ……
反证：若 ____ 成立，则本结论作废。
置信度：高 / 中 / 低 —— 因为 ____。
```

写卡的三条硬规则：

- 结论句里不能出现「可能」「或许」「有待观察」；不确定性放置信度和反证。
- 三个数字必须是**决定性的**，不是随便三个数。
- 动作要能执行；「建议关注」不算动作。

## 二、正文

- 按问题组织，不按「背景—现状—趋势—建议」套模板。
- 每节第一行是本节结论（≤2 句），后面才是论证。
- 小标题写结论，不写主题词：「A 类客户付费意愿高」优于「客户分析」。
- 一段 ≤5 行；一段只说一件事。
- 超过 3 项且要精确比对，用表格；表格紧跟引用它的段落。
- 因果、权衡、判断用文字，不硬做图；要做图就一图一个信息，标题写结论。
- 全部用「事实 / 推断 / 判断」标注；推断标「（推测）」。

### 推荐骨架（专题 L2）

```
# 题目（结论式）
> 日期 · 深度 · 证据数 · 一句话结论

## 结论卡
## 关键发现（3 条，每条：发现 → 证据 → 所以呢）
## 正文
### 1. 子问题一（标题即结论）
### 2. 子问题二
### ……
## 反方与风险（什么会推翻结论）
## 待核与未获取
## 口径与假设
## 来源（E 编号表）
```

简报 L1 砍到：结论卡 → 关键发现 → 2–3 节正文 → 待核 → 来源。

## 三、语言

### 用

- 短句；一句话一个意思。
- 动词开头：做、改、停、投、换、招。
- 具体名词和数字：「3 家」「12 个月」「客单价 2.8 万元」。
- 因果用「因为……所以……」，不用「随着……的推进，……不断深化」。
- 术语第一次出现：先用人话说明它解决什么问题，再给一个例子；英文全称、中文译名放在后面，译名不算解释。
- 英文缩写保留，首次给中文；但只给中文仍不算讲清楚，见第七节。

### 不用

- 空话：进一步、不断、切实、扎实、有力、全面、深度赋能。
- 套话开头：随着……的不断发展、在当今……背景下、众所周知。
- 套话结尾：综上所述、由此可见、总而言之。
- 对冲：可能、或许、一定程度上、有待进一步观察（结论里不用；待核里可以）。
- 假精确：87.3%、提升 23.7%（没有来源就不写小数）。
- 自指：本文、本报告、笔者、我们（除非真代表团队）。
- 制作说明：本报告分为三部分、接下来将从……展开、数据来源于网络。
- 营销词：赋能、抓手、闭环、生态、护城河（除非引用原文并解释）。

### 中文报告四件套

1. 结论先行。
2. 每个数字带来源、时间、口径。
3. 事实与判断分开。
4. 给动作，不给「建议关注」。

## 四、长度

| 档 | 字数 | 删减顺序 |
|---|---|---|
| L0 | ≤300 | 只留答案 + 来源 |
| L1 | ≤1500 | 先删背景，再删重复，最后删形容词 |
| L2 | 4000–8000 | 先删与主结论无关的子问题，再删证据堆砌 |
| L3 | 矩阵 + ≤2000 结论 | 矩阵放附录，正文只留结论 |
| L4 | 按框架 | 细节进附录 |

超长时问：删掉这一段，读者会损失什么？答不上来就删。

## 五、去 AI 味（研究版）

研究文本的 AI 味不在词，在**没有判断**。以下是最常见的五种：

| 症状 | 例子 | 改法 |
|---|---|---|
| 三段式排比 | 「一是……二是……三是……」全是抽象名词 | 改成具体动作和时间 |
| 每段等长 | 五段各三行，像模板 | 重要的写长，不重要的写一句或删 |
| 只描述不判断 | 「市场规模持续扩大，竞争日益激烈」 | 给数字、给谁在赢、给我们的位置 |
| 过度 hedge | 「在一定程度上可能对……产生一定影响」 | 直接说影响谁、多大、什么时候 |
| 引用墙 | 文末 30 个链接，正文没有编号 | 正文内联 `[E##]`，文末只列用到的 |

正向做法：每段至少一个**只有这份研究才有**的事实、数字或判断。没有就删。

## 六、交付前语言自查

- [ ] 每节第一行是结论吗？
- [ ] 小标题是结论还是主题词？
- [ ] 有没有一段超过 5 行？
- [ ] 有没有连续三段都是「描述」没有「判断」？
- [ ] 有没有禁用词？
- [ ] 每个数字有 `[E##]` 吗？
- [ ] 读者只看结论卡和一屏，能不能做决定？
- [ ] 全文删掉 20%，信息有没有减少？没有减少说明本来就该删。

## 七、讲清楚：从「有解释」到「读者能复述」

> 这一节是 2026-10-20 Palantir/FDE v1 验收失败后补的。失败的根因不是资料少，是「术语给了译名，但没有让人懂」。

### 先判断：读者要「懂」还是要「拍板」

- 要拍板：结论先行、数字、动作、反证；读者已有背景。
- 要懂：场景先行、人话、例子、术语后置；读者没有背景。
- 一份报告只能有一种主目标。原话同时要「是什么」和「怎么用」时，拆成两篇或两部分，不合并。

### 术语四步（缺一不出现）

1. **人话定义**：它解决什么问题，不用行业词。
2. **一个例子**：在读者熟悉的场景里，它长什么样。
3. **一个反例/常见误解**：没有它会怎样，或者大家常把它误当成什么。
4. **一句「所以呢」**：对读者/本课题意味着什么。

只给英文全称、中文译名、缩写表，都不算解释。读者能用自己的话复述，才算过。

### 教学型文本的六条硬规则

- 标题用问题，不用「概念澄清」「方法论内核」；标题里不出现读者还没见过的角色名、框架名。
- 第一节先讲读者熟悉的场景/问题，不先讲角色表、框架名、证据编号。
- 一段一个概念；一段不超过 5 行；新术语出现前，先给例子。
- 一个贯穿案例；每节至少一个例子；没有例子的段落删掉或补例子。
- 正文只留 8–10 个关键 `[E##]`；其余进附录，别让引用编号盖过解释。
- 每节结尾回答「所以呢」；答不上来，说明这节可以删。

### 读者测试（L2 教学型必做）

- 3 位读者：目标读者、业务负责人、培训讲师；各读一遍，不看答案。
- 5 个问题：核心概念是什么、为什么有效、角色怎么配合、哪部分可迁移、下一步做什么。
- 至少 4/5 能复述才算过；记录 `reader-test-vN.md`，不通过先改再交。
- 读者复述时用了原文没有的词、或把两个概念混在一起，算失败。

### 两个常见借口

- 「读者应该具备背景」：背景是作者假设，不是读者事实；brief 里写清读者起点。
- 「已经给了英文全称/中文译名」：译名只解决「叫什么」，不解决「是什么、为什么、怎么用」。
