# 分析框架（03）

> 框架用来提问，不用来当内容。判断标准只有一条：用完这个框架，能不能给出一个别人能反驳的具体结论。
> 填满 SWOT 四格但没有「所以呢」，等于没分析。

## 一、先选问题，再选框架

| 要回答的问题 | 框架 | 必须产出 |
|---|---|---|
| 外部环境会怎么变 | PESTEL | 哪 2 个变量真会变、影响谁、什么时候 |
| 这个行业赚不赚钱 | 五力 | 哪股力在变、对谁有利、利润往哪流 |
| 一家公司强不强 | 价值链 + SWOT | 优势的来源、能不能维持、弱点会不会致命 |
| 市场有多大 | TAM/SAM/SOM | 自上而下与自下而上两算，交叉验证，给区间 |
| 商业模式成不成立 | 单位经济 | CAC、LTV、回本周期、毛利率，什么假设下成立 |
| 客户为什么买 | JTBD | 真实替代品是谁、现在怎么凑合、付费触发点 |
| 政策影响 | 政策分析链 | 谁被管、要做什么、什么时候、不做的后果 |
| 几个对象怎么选 | 对标矩阵 | 维度、权重、每格证据、结论排序 |
| 值不值得合作 | 尽调框架 | 主体、业务、财务、履约、风险红旗 |

## 二、逐个框架的用法

### PESTEL（宏观）

只保留**真会变**的 2–3 个变量，其余写「稳定，不展开」。

- Political：监管方向、地方招商、行业协会态度。
- Economic：利率、地产投资、企业 IT 预算。
- Social：人口、就业、AI 焦虑、培训需求。
- Technological：模型能力、成本下降、开源生态。
- Environmental：绿色建筑、能耗（房地产 AI 常相关）。
- Legal：数据合规、算法备案、资质。

产出：每个变量写「往哪变、多快、影响谁、我们该做什么」。

### 五力（行业利润）

- 现有竞争：玩家数、集中度、价格战。
- 新进入者：门槛（资质、数据、渠道、品牌）。
- 替代品：客户现在用什么凑合（Excel、外包、通用大模型）。
- 供应商：模型/算力/内容/讲师谁有议价权。
- 买方：客户集中度、切换成本、招标规则。

产出：哪股力在增强/减弱；利润会被谁拿走；我们应该站在哪一边。

### 价值链 + SWOT

- 价值链：研发 → 内容 → 交付 → 获客 → 服务 → 复购；每段谁做、成本、壁垒。
- SWOT 只写**有证据**的项；每项标来源。
- 优势要问：能不能维持 12 个月？能不能被复制？
- 弱点要问：会不会致命？有没有办法绕开？

产出：一句话「我们的位置是 ____，靠 ____ 赚钱，最大的威胁是 ____」。

### TAM / SAM / SOM（市场大小）

两种算法都要有：

- 自上而下：总市场 × 可服务比例 × 可得比例；每个乘数写假设与来源。
- 自下而上：目标客户数 × 渗透率 × 客单价；客户数从统计/名单来，客单价从官网/招标来。

交叉：两算差 3 倍以上，说明假设有一个错了，回去查。

产出：区间（不是单点）+ 关键假设 + 什么情况下高/低。

### 单位经济

```
毛利 = 客单价 − 直接交付成本（讲师、场地、内容、证书）
CAC = 获客总投入 / 新客户数
回本周期 = CAC / 月毛利
LTV = 客单价 × 复购次数 × 毛利率
```

产出：在什么客单价、什么获客成本下成立；最敏感的是哪个变量。

### JTBD（客户为什么买）

- 客户雇这个产品来完成什么「任务」？
- 现在用什么替代？为什么不够好？
- 什么触发他掏钱（合规、考核、晋升、招标要求）？
- 不买会怎样？

产出：一句「客户买的不是 ____，是 ____」；据此改产品/定价/话术。

### 政策分析链

1. 发文机关、文号、发布日、生效日、效力层级。
2. 目标：解决什么问题。
3. 工具：准入、补贴、考核、标准、试点、处罚。
4. 受影响主体：谁必须做、谁鼓励做、谁被限制。
5. 时间表：什么时候截止、什么时候检查。
6. 受益/受损链条：钱和资源往哪流。
7. 不确定性：执行力度、地方差异、配套细则。

产出：一页「对我们意味着什么 + 三件必须做的事」。

### 对标矩阵

- 维度 5–8 个，从决策需要来（价格、交付、证书、获客、客户、能力、风险）。
- 每格：值 + 来源；没有写「未获取」，不猜。
- 权重只在真要排序时给，并说明理由；不打 0–100 总分，用「强/中/弱」或直接排序。
- 结论：谁在哪个场景更适合；我们该学哪一点、不该学哪一点。

### 尽调框架

主体与股权 → 业务与客户 → 财务与现金流 → 合同与履约 → 合规与诉讼 → 团队 → 风险红旗 → 交易建议。

红旗优先于面面俱到：先列「会让你不签的事」，再补细节。

## 三、量化纪律

- 每个数字带：来源、时间、口径、单位。
- 预测给区间和假设，不给单点；写「若 A 成立则 X，若 B 成立则 Y」。
- 不把相关当因果；看到相关，先找机制或反例。
- 不把行业增速直接套到单一公司；公司有份额、执行、竞争。
- 不把「市场大」当「我们能赚」；中间隔着可服务市场、竞争、交付能力。
- 算不清就写「算不清，需要 ____ 数据」，不硬编。

## 四、二阶与反方

每个主结论做三个动作：

1. **二阶影响**：如果成立，客户/竞品/监管会怎么反应？六个月后格局会怎样？
2. **最强反方**：站在最懂行的反对者角度，写他最强的三条论据；逐条回应。
3. **事前验尸**：假设 12 个月后这个判断被证明错了，最可能的原因是什么？现在能不能排除？

## 五、不同课题的分析重点

| 课题 | 重点 | 容易漏 |
|---|---|---|
| 行业/市场 | 需求真实性、谁付钱、钱从哪来 | 把「关注度高」当「付费意愿高」 |
| 竞品/对标 | 定价、交付、获客、续费 | 只看功能，不看交付成本和续费率 |
| 政策/标准 | 原文、时间表、执行力度 | 把征求意见稿当正式稿 |
| 技术/选型 | 实测、限制、总拥有成本 | 只看 demo，不看失败率和迁移成本 |
| 培训/课程 | 招生、完课、证书、复购 | 把报名数当收入，把满意度当效果 |
| 合作/尽调 | 履约记录、现金流、诉讼 | 只看宣传，不查被执行和投诉 |
